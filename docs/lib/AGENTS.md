# DOCS DATA LAYER

## SCOPE
`docs/lib/` owns filesystem-backed documentation and inventory data. Keep route
rendering in `app/` and UI behavior in `components/`; this directory should
expose typed, deterministic data for those consumers.

## WHERE TO LOOK
| Concern | File | Contract |
| --- | --- | --- |
| Markdown pages | `docs.ts` | Reads `content/*.md`, validates frontmatter, and returns pages ordered by `order`. |
| Skill and binary inventory | `inventory.ts` | Consumes `configs/metadata/skills.lock.json`, skill sources, `Cargo.toml`, and the latest Git year. |
| Config inventory | `inventory-config.ts` | Discovers canonical `configs/` categories and builds stable docs/source links. |
| Repository roots and JSON checks | `inventory-shared.ts` | Resolves checkout versus exported `source/` roots and validates boundary values. |
| Skill URLs and anchors | `anchors.ts` | Centralizes stable path, href, and anchor normalization. |

## BOUNDARIES
- `docs.ts` is the owner of Markdown discovery and frontmatter parsing. Require
  `title`, `eyebrow`, `description`, finite numeric `order`, and typed sections
  before data reaches a route.
- Inventory code reads canonical repository inputs. Do not copy skill,
  attribution, license, or Cargo metadata into TypeScript constants.
- Preserve the exported-site fallback in `inventory-shared.ts`: local
  development reads the parent repository, while packaged docs read `source/`.
- Keep filesystem, JSON, TOML, and Git parsing at this boundary. Components
  should consume the exported types instead of reopening repository files.

## DETERMINISM AND CACHING
- Sort filesystem-derived names, collections, licenses, and skills before
  returning them. Directory enumeration order is not a public contract.
- Validate untyped JSON and frontmatter immediately; include the failing field
  in errors rather than accepting partial records.
- Use React `cache()` for server-side reads shared by route generation and
  rendering. Do not add module-global mutable caches or stale generated copies.
- Keep absent optional provenance nullable and reserve fallback text for fields
  whose type explicitly allows it.

## GENERATED INPUTS
- `configs/metadata/skills.lock.json` is generated by the Rust metadata flow;
  update its source or refresh command instead of hand-editing values.
- `docs/source/`, `docs/out/`, `docs/.next/`, and mirrored files under
  `docs/public/` are generated outputs. Never fix inventory behavior there.

## VERIFICATION
```bash
npm run docs:typecheck
npm run docs:build
```
- After Markdown-loader changes, open a representative docs page such as
  `/docs/getting-started` and confirm navigation follows frontmatter order.
- After inventory or anchor changes, open a real `/docs/skills/...` route and
  verify metadata, source links, and missing-path behavior against canonical
  files.
- Build validation covers static route generation; browser QA covers rendered
  metadata and links. Exercise the `source/` fallback when changing root
  resolution or export packaging.
